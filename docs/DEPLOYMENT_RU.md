# Публикация с хранением ответов в РФ

Подготовлена конфигурация для Amvera, регион **Россия**. Наличие этих файлов не означает, что приложение уже опубликовано. Нужен аккаунт владельца; платный ресурс создаётся после согласования тарифа.

## Настройка приложения

1. В [панели Amvera](https://cloud.amvera.ru/) создайте приложение в российском регионе, одну реплику. Не выбирайте зарубежные регионы.
2. Подключите репозиторий `https://github.com/ivanfix2005/tail-landing`, ветку `main`. Сборка использует `Dockerfile` и `amvera.yaml` из корня. npm install для сервера не нужен.
3. В переменных приложения проверьте `HOST=0.0.0.0`, `PORT=8790`, `DATABASE_PATH=/data/tail.sqlite`. Не загружайте локальную базу с ответами в репозиторий.
4. В разделе «Домены» добавьте бесплатный домен Amvera с HTTPS. Скопируйте полученный origin без завершающего слэша в `PUBLIC_ORIGIN`. Это адрес вида `https://имя-проекта.имя-владельца.регион.amvera.tech`, точный адрес покажет панель провайдера.
5. Обновите адрес сайта в `public/privacy/index.html` и обеих страницах `public/consent/`. Проверьте фактические реквизиты оператора и инфраструктуру; при содержательном изменении согласий измените версии в `public/survey-model.js`. По умолчанию Метрика выключена.
6. Соберите и запустите приложение. В журнале должна появиться строка «ТЭЙЛ». Проверьте главную, правовые страницы и `/api/health` по HTTPS.

Постоянный каталог `/data` содержит базу и её SQLite WAL/SHM-файлы. При пересборке он сохраняется. Одна реплика необходима для этого варианта с файловой SQLite. Квоты входящего трафика и ограничения запросов проверяются в панели провайдера.

## Проверка перед распространением ссылки

- Открыть сайт с другого устройства и проверить формы и анимации на телефоне.
- Сохранить один явно искусственный тестовый ответ, проверить появление записи в закрытом хранилище и её сохранность после перезапуска. Удалить только этот тест до начала реального сбора.
- Проверить, что `.env`, `/data/tail.sqlite` и выгрузки не доступны по HTTP. В приложении нет открытого API чтения ответов.
- Настроить резервное копирование в российском регионе. Доступ к бэкапам зависит от тарифа провайдера. Для ручной копии остановить приложение и скачать базу вместе с оставшимися WAL-файлами; после копирования снова запустить. Не публиковать базу и выгрузки на GitHub.

Обновления: изменения проходят проверку и Pull Request, после принятия в `main` владелец запускает пересборку либо включает автоматическое развёртывание в панели. Открытый код не даёт участнику доступа к ответам или аккаунту хостинга.
